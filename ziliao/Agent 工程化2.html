Oh My OpenAgent (原 oh-my-opencode)

最激进的多智能体系统 · 基于哈希的编辑 · 完全兼容 Claude Code

🎯 核心命令

ultrawork 或 ulw — 一键触发，所有智能体出动，任务完成前绝不罢休

🪄 自律军团 (Discipline Agents)

Sisyphus（指挥官）调度 Hephaestus（深度工作者）、Prometheus（规划师）、Oracle、Librarian 和 Explore

👥 Team Mode (v4.0)

领导 Agent + 最多 8 个并行成员，实时 tmux 可视化，专用 team_* 工具家族

🔗 基于哈希的编辑工具

LINE#ID 内容哈希验证，0% 错误修改。在 Grok Code Fast 1 上修改成功率从 6.7% 飙升至 68.3%

🛠️ LSP + AST-Grep

工作区级别的重命名、构建前诊断、基于 AST 的重写，为 Agent 提供 IDE 级别的精度

🧠 后台智能体

同时发射 5+ 个专家并行工作，保持上下文干净，随时获取成果

📚 内置 MCP

Exa（网络搜索）、Context7（官方文档）、Grep.app（GitHub 源码搜索），默认开启

"如果人类需要 3 个月完成的事情 Claude Code 需要 7 天，那么 Sisyphus 只需要 1 小时。它会一直工作直到任务完成。"

Oh My Codex (OMX)

OpenAI Codex CLI 的多智能体编排层 · 原生 Rust 探索 · 深度访谈工作流

🎯 推荐工作流

$deep-interview → $ralplan → $team 或 $ralph

⚡ v0.9.0 Spark Initiative

原生 Rust harness 更快、更严格地执行只读仓库探索；sparkshell 面向操作者的原生检查界面

🔍 深度访谈 (Deep Interview)

当范围或边界还不清楚时，先用它澄清需求，苏格拉底式提问揭示隐藏假设

📋 Ralplan 规划

把澄清后的范围整理成可批准的架构与实施计划

👥 团队模式

生命周期：start → assign scoped lanes → monitor → verify terminal tasks → shutdown

🔌 Hooks 扩展

插件脚本手架和验证，插件文件位于 .omx/hooks/*.mjs

🎨 启动标志

--yolo, --high, --xhigh, --madmax, --force, --dry-run, --verbose, --scope

优缺点对比

每个工具的优势和注意事项

Oh My OpenAgent

优点：
  • 基于哈希的编辑，零错误
  • 极高的并行能力
  • 完整的 LSP + AST 集成
  • 完全兼容 Claude Code
  • 自律军团架构独特
缺点：
  • 学习曲线中等
  • 配置相对复杂
  • 需要 OpenCode 基础

Oh My Codex

优点：
  • 原生 Rust 性能
  • 深度访谈工作流
  • 精细的团队控制
  • Hooks 扩展系统
  • 丰富的启动标志
缺点：
  • 仅支持 Codex CLI
  • 学习曲线中等
  • 社区相对较小

Oh My ClaudeCode

优点：
  • 零学习曲线
  • 自然语言交互
  • 32 个专业智能体
  • 技能自动学习
  • 成本优化优秀
  • 社区活跃
缺点：
  • 需要 Claude Code
  • 编辑工具无特殊优化
  • 并行能力相对较低

总结与建议

如何选择适合你的工具

🎯 选择建议

追求极致性能和精确性 → Oh My OpenAgent

使用 OpenAI Codex 生态 → Oh My Codex

快速上手，零学习曲线 → Oh My ClaudeCode

🚀 Oh My OpenAgent

适合需要极致并行执行、编辑精确性、多模型混合的复杂项目。如果你愿意投入时间学习配置，它会给你带来最大的生产力提升。

⚡ Oh My Codex

适合已经使用 OpenAI Codex 的开发者，特别是需要深度访谈澄清需求、精细控制工作流的场景。原生 Rust 性能优势明显。

🎨 Oh My ClaudeCode

适合想要快速上手、自然语言交互的开发者。32 个专业智能体和技能自动学习系统让开发变得轻松，成本优化也很出色。

💡 共同特点

三个工具都提供多智能体编排、团队模式、技能系统、MCP 支持。选择哪个主要取决于你的基础平台（OpenCode/Codex/Claude Code）和个人偏好。
