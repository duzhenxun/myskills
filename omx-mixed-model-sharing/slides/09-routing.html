ROUTING STRATEGY
ROLE ≠ CLI ≠ MODEL
把三个概念分开，配置才不会乱

角色决定怎么做，CLI 决定谁来做，模型参数决定用哪一档

层负责什么例子建议
Role任务职责、行为约束、交付格式executor / architect / verifier按任务形状选，不按厂商选
CLI实际启动哪个本地 agent 程序codex / claude / gemini通过 OMX_TEAM_WORKER_CLI_MAP 指定
Model某个 CLI 内部使用的具体模型由账号、CLI 配置和启动参数共同决定先跑默认，再按当前 CLI 文档覆盖

推荐拆法

实现 / 架构审阅 / 测试验证三条 lane，任务边界清晰且能相互校验。

不推荐拆法

仅按“前端给 Gemini、后端给 Codex”硬绑定；仓库结构和任务风险往往比厂商标签更重要。
